## Reporting a Vulnerability

We take security vulnerabilities seriously. If you discover a security vulnerability within RJ BlocX CLI, please follow these steps:

### How to Report

1. **Do NOT create a public GitHub issue** for security vulnerabilities
2. Send an email to **rahulverma0549@gmail.com** with the subject line: `[SECURITY] RJ BlocX CLI Vulnerability Report`
3. Include the following information:
   - Description of the vulnerability
   - Steps to reproduce the issue
   - Potential impact and severity
   - Any suggested fixes or mitigations
   - Your contact information for follow-up

### What to Expect

- **Acknowledgment**: We will acknowledge receipt of your report within 48 hours
- **Investigation**: We will investigate and assess the vulnerability within 5 business days
- **Updates**: We will provide regular updates on our progress
- **Resolution**: We aim to resolve critical vulnerabilities within 30 days
- **Credit**: We will credit you in our security advisories unless you prefer to remain anonymous

### Security Best Practices

When using RJ BlocX CLI:

1. **Keep Updated**: Always use the latest version of RJ BlocX CLI
2. **Validate Input**: Be cautious with project names and file paths
3. **Review Generated Code**: Always review generated code before using in production
4. **Dependency Management**: Regularly update dependencies in generated projects
5. **Environment Security**: Use the tool in trusted environments only

### Scope

This security policy covers:

- RJ BlocX CLI tool itself
- Generated project templates and code
- Dependencies and package management features
- File system operations and project creation

### Out of Scope

- Third-party packages installed via the CLI
- Flutter framework vulnerabilities
- Generated project runtime vulnerabilities
- User-specific configuration issues

## Security Features

RJ BlocX CLI includes several security features:

- Input validation for project names and paths
- Safe file system operations with proper permissions
- Secure template generation without code injection
- Dependency verification for package additions
